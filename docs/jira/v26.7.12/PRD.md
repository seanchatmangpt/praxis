## 1. Product Decision

v26.7.12 SHALL implement, in a single new crate (`crates/multifractal-workflow`), one module per
architecture family named in the mermaid atlas (F01–F30, tickets V12-001..V12-030).

The crate SHALL achieve real reuse of existing praxis code, real adaptation of existing code
outside this repo (under `/Users/sac/`), and real `crates/ggen`-generated scaffolding for the
majority of its content — the explicit target, stated by the product owner, is that a human
should only need to hand-write approximately 20% of the total. See
`tickets/index.md` § Hand-written percentage for the actual measurement against that target.

`docs/jira/v26.7.11/ADVERSARIAL_DOD.md` — those remain reserved for the v26.7.11 orchestrating
session.

The only permitted ggen target is `crates/ggen` in this repo.

## 3. Generation Strategy

Per family, the atlas survey (an inline research pass, not itself a checked-in repo doc — see
each module's own doc comment for what it independently re-confirmed against the atlas file this
session) classified content into up to three buckets, used by every ticket in
`tickets/index.md`:

1. **ALREADY_BUILT / REUSE_ADAPT** — real, already-tested praxis code (or code under
   `/Users/sac/` outside this repo) thinly wrapped or pattern-adapted, not reimplemented.
2. **GGEN_GENERATABLE** — vocabulary, lifecycle-state catalogs, or provenance-chain scaffolding
   generated by a real `crates/ggen` pack (`packs/f<NN>-*-pack/`) via `ggen sync run`, verified
   byte-identical across repeated runs.
3. **HAND_WRITE_REQUIRED** — genuinely novel logic with no existing analog anywhere in scope;
   where not yet built this pass, implemented as a typed refusal that always fails loud
   (never a silent placeholder success).

## 4. Non-Goals This Pass

- A second interpreter of AIR semantics in Rust (F15/F17's own family invariant forbids this;
  the Erlang transition core remains authoritative).
- Cross-process/restart-durable idempotency ledgers for families whose disclosed L7 gap notes
  in-memory-only state (see `tickets/index.md` for which families this applies to).
- Full OWL-RL semantic closure, ShEx-CONSTRUCT, or SPARQL-CONSTRUCT-based derivation surfaces
  beyond what each family's own module doc comment claims.
- Editing `docs/jira/v26.7.11/tickets/index.md` or `ADVERSARIAL_DOD.md`.
