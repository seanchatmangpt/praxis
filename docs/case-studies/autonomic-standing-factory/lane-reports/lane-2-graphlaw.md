## Failures found

1. N3 text-syntax gotcha: a `not { ?x a :Class }` `BodyLiteral` never
   consumes a trailing `.` in this crate's grammar (`n3.pest`'s
   `BodyLiteral = { ("not" ~ "{" ~ TP ~ "}") | TP }` has no optional
   period after the `not{}` alternative, unlike a plain `TP`, which does).
   Writing `not { ... } .` between two body literals produced a parse
   error ("expected ForAll, ForSome, or TP"). Fixed by removing the
   spurious period after every `not { ... }` block.
2. Datalog safety-check rejection: an early draft of
   `ExternalSideEffectsSeparated` negated an unbound variable
   (`not { ?x a praxis:BlockingSideEffect }` with `?x` free in no positive
   literal) — `datalog.rs::validate_rules`'s range-restriction check
   correctly rejects this as unsafe. Fixed by deriving an intermediate
   `praxis:HasBlockingSideEffect` fact on the case-study subject first,
   then negating that (shared, positively-bound `?cs`).
3. Design risk avoided before it became a bug: verdict facts were
   originally sketched as `?cs praxis:hasVerdict praxis:<Verdict>` (shared
   predicate, 3 different object constants). Tracing
   `datalog.rs::relation_of` showed this collapses to one stratification
   relation for all 3 verdicts, making the mutually-exclusive negation
   between them an unstratifiable self-loop. Switched to `rdf:type` class
   membership per verdict (this crate's own "object-as-relation for `a`
   patterns" heuristic keeps each verdict its own relation) before ever
   attempting to load the file, avoiding the rejection entirely.

None of these were pre-existing defects in `praxis-graphlaw` — all three
were authoring mistakes in this lane's own new N3/Datalog text, caught by
the crate's existing safety/stratification checks working exactly as
designed, and fixed forward in the same files before this lane's tests
were declared green.
