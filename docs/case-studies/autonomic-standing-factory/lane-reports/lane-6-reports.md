**Real bug fixes found during this lane's own verification work:**

- `src/bin/case_study_judge.rs` — `verdict_present`'s original SPARQL query
  (`SELECT ?cs WHERE { <ground-subject> a <ground-class> }`) never bound
  its projected `?cs` variable (the WHERE clause is fully ground), so
  `query_first_col` (which extracts the first BOUND binding per row)
  silently discarded every solution row — `verdict_present` returned
  `false` unconditionally, for every verdict class, on every call, and
  `run()`'s `verdict` always fell through to its hardcoded
  `.unwrap_or("NotReadyWithReasons")` default. This went undetected because
  that default happened to equal the correct answer for every case-study
  state that existed before this lane's evidence promotion. Fixed by
  mirroring the working `case_study_subjects` query shape (`SELECT ?s
  WHERE { ?s a <class> }` — variable subject, so it actually binds) and
  checking subject-IRI membership in the results. Added a regression test,
  `verdict_present_finds_a_genuinely_asserted_class`, that exercises the
  fixed function directly (the pre-existing `present()` test helper never
  had this bug, since it checks the raw row count rather than going
  through `query_first_col`). Full root-cause narrative, including a
  second, disclosed-but-not-fixed graph-consistency artifact of the
  judge's multi-pass `materialize()` design, is in
  `GRAPHLAW_JUDGMENT_MODEL.md`.
- `crates/ggen/tests/dogfood_regression.rs` — found while running `just
  verify-all`: `ggen_regenerates_route_files_byte_identically` failed with
  `[FM-PACK-001] pack standing-pack: directory .../cargo-cicd/plugins/
  cargo-cicd-kit/standing-pack does not exist`. Root cause: `ggen.toml`'s
  `[packs]` table declares `standing-pack = { path =
  "../cargo-cicd/plugins/cargo-cicd-kit/standing-pack" }` (a real,
  sibling-repo path that resolves fine for the actual checkout), but this
  test stages its inputs into an isolated `TempDir` where that relative
  `../` no longer resolves to the real sibling directory — the standing
  pack was never part of the test's staged input closure. Fixed by staging
  `stage` one level inside a dedicated, exclusively-owned `outer` tempdir
  and additionally copying the real `/Users/sac/cargo-cicd/plugins/
  cargo-cicd-kit/standing-pack` directory to the matching sibling location
  inside `outer`, so the tempdir is a genuinely self-contained input
  closure (matching the test's own stated design intent in its existing
  comments). Unrelated to any case-study lane's own work — a pre-existing
  gap exposed by the standing-schema deliverable's `[packs]` addition,
  never previously exercised by this specific tempdir-isolated test.
