## Gate C — Tests

1. Acceptance suite is generated by ggen from fail-loud templates; zero assert-free
   tests exist in the generated output (the 8 dispatch files
   `tests/chatman_acceptance_{admission,agents,hooks,receipts,replay,routing,static,triple8}.rs`).
2. Test surface: flat `tests/chatman_*.rs` files plus the
   `tests/chatman_engine_acceptance/` harness+fixtures tree. Scenario-style tests go
   through the `chicago-tdd-tools` harness macros (`test!`, `param_test!`).
   **Raw-`#[test]` carve-out** — the following categories are not ordinary scenario
   tests and may use raw `#[test]`, provided each file states its category in its
   module doc comment: (a) ggen-generated dispatch acceptance files (regenerated, not
   hand-edited); (b) static filesystem-scanning gates (`chatman_static_gates.rs`);
   (c) spec-theorem gates (`chatman_spec_theorems.rs`); (d) structural/governance
   tests whose assertions drive the engine directly (receipts-chain, refusal
   governance, hot-path, CLI sabotage, hooks-OCEL) and `proptest!`-internal `#[test]`
   items. Tests must remain non-vacuous and assertion-full; no test mechanics are
   rewritten for cosmetic conformance.
3. All static gates green.
4. Chatman Constant tick gate holds on `AdmissionTable8::lookup` (bounded-tick
   admission; the gate test fails if lookup exceeds the constant).

Gate E is **Chatman-scoped**: it grades `crates/praxis-graphlaw/src/chatman/` and the
Chatman test/evidence surface (`tests/chatman_*.rs`, `tests/chatman_engine_acceptance/`).
Crate-wide clippy failures outside that surface are recorded as excluded preexisting
debt (named exclusion 6 above), not Gate E failures.

1. `cargo fmt --check` clean on the Chatman surface; full crate-wide
   `cargo clippy --all-targets -- -D warnings` output captured, with zero findings in
   Chatman-surface files (out-of-surface findings listed as preexisting debt).
2. No forbidden production tokens in `src/chatman/`: `.unwrap()`, `.expect(`, `panic!(`,
   `todo!(`, `unimplemented!(`, `unwrap_or_default`, bare `.ok()`, `SystemTime`,
   `Instant::now`, `unsafe` (test modules exempt for assertion-context unwraps).
3. No duplicate canonical `pub struct`/`pub enum` names across `src/chatman/*.rs`.
4. Mutation score >= 80% on `src/chatman` (advisory for this closure; capture output).
5. Line coverage >= 85% on `src/chatman` (via `cargo llvm-cov`; tarpaulin not installed).

## Gate F — Verdict

The builder never self-grades. An independent auditor (a session that did not write
the code) runs Gates A–E and writes the only status line into
`docs/chatman-engine/chicago_tdd_final_report.md`. Permitted statuses:

- `ADMITTED_DRY_RUN_PUBLISHABLE` — all gates pass with cited command output.
- `PARTIAL` — named gaps, each with the failing gate and file:line.
- `REFUSED` — a binding invariant is violated; cite the invariant.

Any status written by the builder, or any status outside this vocabulary, is void.

Closure-run override (per `docs/chatman-engine/evidence/no_gap_blocker_policy.md`): for the
v26.7.9 closure run, `PARTIAL` is not an accepted terminal status — only
`ADMITTED_DRY_RUN_PUBLISHABLE` or `REFUSED_WITH_NONLOCAL_BLOCKER` (the latter replaces
`REFUSED` and requires citing a genuinely nonlocal blocker).
