# Chatman Engine v26.7.9 — Definition of Done

Version: v26.7.9. Updated 2026-07-09.

This document defines the binding gates that must all pass before any Chatman Engine
artifact is claimed done. It is the authoritative path-and-substrate spec for the engine;
where the v26.7.8 ticket specs (PROJ-411..414) disagree on paths or dependency details,
this document supersedes them. Status vocabulary follows
`.claude/rules/no-overclaiming.md`; readiness policy follows
`docs/standing/CLAUDE_CODE_POLICY.md`.

## Quick Reference

1. Gate A — Substrate (toolchain, oxrdf/oxigraph pinning, rdf-12 refusal boundary)
2. Gate B — Code (module set, Refusal taxonomy, sealed admission, receipt envelope)
3. Gate C — Tests (generated acceptance suite, combinatorial invariants, tick gate)
4. Gate D — Evidence (ggen sync byte-identity, OCEL seals, determinism)
5. Gate E — Quality (fmt, clippy, dylint, mutation, coverage)
6. Gate F — Verdict (independent auditor writes the only status)

## Gate A — Substrate

All of the following hold simultaneously:

1. Toolchain pinned to `nightly-2026-06-22` in `rust-toolchain.toml`.
2. No `oxigraph-local` or `oxrdf-patched` entries in any `[patch]` section — the
   workspace builds against upstream crates only.
3. Exactly one `oxrdf` in the dependency graph, pinned `=0.3.3`.
4. `oxigraph 0.5.9` with the `rdf-12` feature ON; RDF 1.2 triple terms that reach the
   receipt boundary are refused via the `TripleTermInSnapshot` Refusal variant — never
   silently serialized or dropped.

Verification:

```bash
grep -n "nightly-2026-06-22" rust-toolchain.toml
grep -nE "oxigraph-local|oxrdf-patched" Cargo.toml && echo "FAIL: local patches" || true
cargo tree -e normal | grep -c "oxrdf v0.3.3"   # every oxrdf line is =0.3.3, one version
cargo tree -e normal | grep "oxigraph v0.5.9"
cargo tree -e features -p praxis-graphlaw | grep "oxigraph.*rdf-12"
grep -rn "TripleTermInSnapshot" src/chatman/
```

## Gate B — Code

1. Module set exists and compiles: `src/chatman/abi.rs`, `src/chatman/triple8.rs`,
   `src/chatman/admission8.rs`, `src/chatman/router.rs`, `src/chatman/engine.rs`,
   `src/chatman/bridge.rs`.
2. `Refusal` enum has exactly 29 variants, each specific, documented, and returned
   somewhere (no dead variants, no catch-alls).
3. `AdmittedTransition` is sealed: its only constructor is receipt-bearing, so
   unreceipted actuation is a compile error, not a runtime check.
4. `ProcessReceiptEnvelope` carries exactly 9 hashes in constitutional order, and
   `verify_replay` re-checks each field independently (per-field, not whole-envelope).

Verification:

```bash
ls src/chatman/abi.rs src/chatman/triple8.rs src/chatman/admission8.rs \
   src/chatman/router.rs src/chatman/engine.rs src/chatman/bridge.rs
grep -c "^\s*[A-Z][A-Za-z0-9]*\s*[({,]" src/chatman/abi.rs  # count Refusal variants = 29
grep -n "mod sealed\|pub(crate) fn\|struct AdmittedTransition" src/chatman/*.rs
grep -n "verify_replay" src/chatman/*.rs
cargo check -p praxis-graphlaw 2>&1 | tail -5
```

## Gate C — Tests

1. Acceptance suite is generated by ggen from fail-loud templates; zero assert-free
   tests exist in the generated output.
2. Combinatorial invariant layer spans 11 test files built on `chicago-tdd-tools`;
   no raw `#[test]` attributes in chatman tests (all go through the harness macros).
3. All static gates green.
4. Chatman Constant tick gate holds on `AdmissionTable8::lookup` (bounded-tick
   admission; the gate test fails if lookup exceeds the constant).

Verification:

```bash
ggen sync --check
grep -rL "assert" tests/chatman/ && echo "FAIL: assert-free test file" || true
ls tests/chatman/*invariant* | wc -l   # expect 11
grep -rn "#\[test\]" tests/chatman/ && echo "FAIL: raw #[test]" || true
cargo test --release chatman_tick_gate
```

## Gate D — Evidence

1. `ggen sync` run twice produces byte-identical output and an intact receipt chain.
2. OCEL seals in `.cargo-cicd/ocel/events.jsonl` re-hash to their recorded digests.
3. `receipt_root` is byte-identical across 5 consecutive runs (determinism invariant).

Verification:

```bash
ggen sync && cp .ggen-v2/receipt.json /tmp/r1.json
ggen sync && diff /tmp/r1.json .ggen-v2/receipt.json && echo "byte-identical"
cargo run -p praxis-graphlaw --bin ocel-verify -- .cargo-cicd/ocel/events.jsonl
for i in 1 2 3 4 5; do cargo test --release receipt_root -- --nocapture \
  | grep receipt_root >> /tmp/roots.txt; done
sort -u /tmp/roots.txt | wc -l   # expect 1
```

## Gate E — Quality

1. `cargo fmt --check` and `cargo clippy -- -D warnings` clean on chatman code.
2. dylint clean (project lints).
3. Mutation score >= 80% on `src/chatman`.
4. Line coverage >= 85% on `src/chatman`.

Verification:

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo dylint --all
cargo mutants --package praxis-graphlaw --file 'src/chatman/*' \
  | grep -E "caught|missed"   # caught / total >= 0.80
cargo tarpaulin --include-files 'src/chatman/*' --out Stdout \
  | grep "Line coverage"      # >= 85%
```

## Gate F — Verdict

The builder never self-grades. An independent auditor (a session that did not write
the code) runs Gates A–E and writes the only status line into
`docs/chatman-engine/chicago_tdd_final_report.md`. Permitted statuses:

- `ADMITTED_DRY_RUN_PUBLISHABLE` — all gates pass with cited command output.
- `PARTIAL` — named gaps, each with the failing gate and file:line.
- `REFUSED` — a binding invariant is violated; cite the invariant.

Any status written by the builder, or any status outside this vocabulary, is void.
