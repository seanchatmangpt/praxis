# Chatman Engine Mermaid Atlas

Welcome to the canonical Mermaid Atlas for the Chatman Engine. This atlas is a hyperdimensional information-preservation artifact designed under the doctrine of Combinatorial Maximalism.

## Design for Combinatorial Maximalism

The Chatman Engine is a high-dimensional semantic object containing RDF authority, graph state, closure, validation, routing, planning, workflow legality, event observation, hook actuation, cognitive breed selection, agent boundaries, receipts, replay, refusals, benchmarks, and CENG governance.

A single diagram is a projection. A projection collapses dimensions. Collapsed dimensions create information loss. Information loss creates interpretation. Interpretation recreates business logic. Therefore, the atlas must generate the maximal non-redundant projection set required to preserve the system under diagrammatic compression.

Use this formal framing:

$$D_i = P_i(H)$$

Where $H$ is the full hyperdimensional state of the Chatman Engine, and $D_i$ is a projection diagram.

The goal is to maximize preserved mutual information:

$$I(H ; \{D_1, D_2, \dots, D_{240}\})$$

subject to non-redundancy.

## Toyota Production System (TPS) Mapping

Design for Combinatorial Maximalism maps directly to the Toyota Production System. The Mermaid atlas is the visual factory floor for the Chatman Engine:
- Each diagram is a **gauge**.
- Each diagram exposes **one defect class**.
- Each diagram **protects flow**.
- Each diagram **prevents one kind of representation drift**.

Examples:
- **Flowcharts** expose routing waste.
- **Swimlanes** expose ownership ambiguity.
- **Sequence diagrams** expose handoff defects.
- **Class diagrams** expose duplicate type creation.
- **State diagrams** expose illegal lifecycle transitions.
- **ER diagrams** expose persistence ambiguity.
- **Gantt diagrams** expose dependency violations.
- **Requirement diagrams** expose unverifiable invariants.
- **Packet diagrams** expose binary-layout ambiguity.
- **Sankey diagrams** expose flow imbalance.
- **Ishikawa diagrams** expose root causes.
- **Wardley diagrams** expose strategic maturity.
- **Cynefin diagrams** expose complexity-domain mismatch.

## Design for Lean Six Sigma (DfLSS) Mapping

The defect is **information loss**.
The Critical to Quality (CTQ) is **zero semantic shadow copies**.
The failure mode is diagrammatic omission becoming ticket omission, then code omission, then process drift.
The control plan consists of **8 projection lenses × 30 diagram families** = 240 diagrams.

Every diagram maps to:
1. A preserved invariant.
2. An information-loss risk.
3. A TPS visual-control purpose.
4. A DfLSS CTQ.
5. A CENG ticket or engine boundary.
6. A non-redundancy justification.

## The 8 Projection Lenses

Every diagram family contains exactly one diagram for each of the following lenses:

### Lens 1 — Semantic Authority
Preserve RDF/Oxigraph as source of truth. Show where semantic authority is maintained and where shadow copies are forbidden.

### Lens 2 — Routing Constitution
Preserve least-expressive-power routing. Show hot path, warm path, cold path, N3 quarantine, and profile gates.

### Lens 3 — Type Kernel Ownership
Preserve canonical ownership across wasm4pm-compat, wasm4pm-cognition, bcinr-pddl, bcinr-powl, and praxis-graphlaw. Prevent duplicate types.

### Lens 4 — Transition Lifecycle
Preserve the lifecycle of an admitted transition from candidate invocation to validation, planning, workflow admission, hook boundary, receipt, and replay.

### Lens 5 — Event / Hook / Actuation
Preserve OCEL event ingestion, Knowledge Hook matching, boundary actuation, and no-unreceipted-actuation.

### Lens 6 — Performance / 8-Constraint Hot Path
Preserve RDFTriple8, ConditionCell<BITS>, 256-state tables, vector-to-mask lowering, benchmarks, and hot/warm/cold latency discipline.

### Lens 7 — Refusal / Risk / Governance
Preserve typed refusal taxonomy, N3 quarantine refusals, profile denial, replay failure, audit gates, and CENG board governance.

### Lens 8 — TPS / DfLSS / Continuous Improvement
Preserve flow, waste removal, WIP reduction, defect prevention, CTQ mapping, measurement, benchmark feedback, and process improvement loops.
