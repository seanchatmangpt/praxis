# What Praxis Does for Projects

Applying the `praxis` system to a project transforms it from a generic Rust codebase into a standardized, structurally verifiable, and highly constrained system that complies with the "Post-Chatman Equation" ($A = \mu(O^*)$). It enforces architectural laws, unified hygiene, and rigorous provenance.

Here is exactly what using the system does for your projects:

## 1. Unified Hygiene & Automation
* **Standardized Configuration:** `praxis` ensures all repositories share the same `[lints]`, `.editorconfig`, `rustfmt.toml`, `deny.toml`, and `typos.toml`, guaranteeing that every developer and agent operates under the exact same constraints.
* **CI/CD Alignment:** Drops in standard GitHub Actions workflows for continuous integration, dependabot updates, and deterministic releases tied to a CalVer versioning scheme (`YY.M.patch`).

## 2. Structural Verification (The Post-Chatman Equation)
* **Generative Typestates:** Projects generated by `praxis` natively use Zero-Sized Types (ZSTs) to represent compilation-gated phase transitions. Transitions like `Raw` -> `Admitted` are strictly enforced using `Evidence<T, State, Witness>`, `Admit` traits, and cryptographic receipts.
* **The Seal Pattern:** Domain objects that must be validated or hashed are forced to use a private `_seal: ()` field. This ensures that valid states cannot be fabricated out of thin air, and must pass through the canonical builder and validation path to compile successfully.
* **BLAKE3 Content Addressing:** Every receipt and artifact is uniquely identified by its BLAKE3 digest over canonical bytes. This prevents tampering and guarantees that the same inputs always produce the same provenance hash.

## 3. Language Server Infrastructure
* **RulePackServer:** Natively outfits projects with `tower-lsp` wrapped structures (`RulePackServer`) that automate text syncing, workspace indexing, incremental AST parsing (via `tree-sitter`), and latency evaluation. This makes spinning up new code-analysis agents and LSPs trivial and law-abiding.

## 4. Ontological Code Generation (`ggen`)
* **Micro-Pipeline Integration:** Natively embeds the `ggen` workflow for building systems driven by ontological definitions. It scaffolds TTL ontology management, inference, SHACL/SPARQL validation, and Tera rendering with unforgeable cryptographic receipts.

## 5. Standardized CLI & Architecture
* **Noun-Verb Dispatch:** Forces CLI applications into a `<noun> <verb>` architecture via `clap-noun-verb`. Argument parsing is completely isolated from business logic execution.
* **Zero-Cost Plugin Discovery:** Uses `linkme::distributed_slice` to allow downstream crates to register handlers without relying on a central registry or runtime scanning, shifting the cost to link-time.

By using `praxis`, a project immediately inherits a rigid backbone of security, determinism, and generative accountability that prevents LLM cheating, enforces architectural laws, and standardizes development at scale.
